# **PROG1400 – Final Project Rubric**

**Capstone: Refactor, Modularize, and Transform an OOP Game**  
**Total: 100 points**

***

## **1. Refactoring & Modularization of Original Code (20 points)**

**Focus:** How well the original monolithic Pac‑Man code was reorganized into a modular project.

| Level          | Description                                                                                                                                    | Points |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| **Excellent**  | Clear, logical multi‑file structure with strong separation of concerns. Classes and systems moved to appropriate modules. No circular imports. | 18–20  |
| **Proficient** | Mostly modular with minor coupling, organizational, or responsibility issues.                                                                  | 14–17  |
| **Developing** | Some modularization attempted, but responsibilities are mixed or inconsistent.                                                                 | 8–13   |
| **Beginning**  | Minimal or ineffective refactoring; project remains largely monolithic.                                                                        | 0–7    |

***

## **2. Object‑Oriented Design & Use of Classes (20 points)**

**Focus:** Effective use of OOP principles such as encapsulation, responsibility, and relationships.

| Level          | Description                                                                                                                                    | Points |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| **Excellent**  | Strong OOP design with well‑defined classes, clear responsibilities, and appropriate relationships (inheritance/composition where applicable). | 18–20  |
| **Proficient** | Good OOP usage with minor design issues or missed encapsulation opportunities.                                                                 | 14–17  |
| **Developing** | Basic class usage; shallow or unclear responsibilities.                                                                                        | 8–13   |
| **Beginning**  | Weak or incorrect use of OOP principles; largely procedural design.                                                                            | 0–7    |

***

## **3. Game Adaptation & Creativity (20 points)**

**Focus:** Degree of **mechanical and conceptual transformation** from the original Pac‑Man interaction model.

> **Key expectation for Excellent:**  
> Once a direction is initiated, the entity continues moving **automatically through all valid paths and turns until physically blocked**. Stopping should occur due to obstruction — not simply because a choice exists.

| Level          | Description                                                                                                                                                                                                                              | Points |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| **Excellent**  | Fundamental transformation of gameplay mechanics. Automatic movement persists until blocked; player input is only required when no continuation is possible. Game clearly differs in rules, mechanics, and objectives from the original. | 18–20  |
| **Proficient** | Clear conceptual transformation with partial implementation of new mechanics (e.g., automatic movement exists but stops at intersections). Meaningful changes to theme and rules.                                                        | 14–17  |
| **Developing** | Limited mechanical change; transformation is mostly thematic or cosmetic with some rule adjustments.                                                                                                                                     | 8–13   |
| **Beginning**  | Game remains largely unchanged from the original interaction model.                                                                                                                                                                      | 0–7    |

***

## **4. Functionality & Gameplay Requirements (20 points)**

**Focus:** Playability, completeness, and stability of the final game.

| Level          | Description                                                                                                                                                 | Points |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| **Excellent**  | Fully playable and stable. Includes movement, game board/levels, challenges or hazards, objectives or collectibles, scoring, and clear win/lose conditions. | 18–20  |
| **Proficient** | Mostly functional with minor bugs or missing polish. All core features are present.                                                                         | 14–17  |
| **Developing** | Partially functional; missing one or more required features or has significant gameplay issues.                                                             | 8–13   |
| **Beginning**  | Game is broken, incomplete, or does not run.                                                                                                                | 0–7    |

***

## **5. Configurability & Code Maintainability (5 points)**

**Focus:** Removal of magic numbers and support for easy tuning or reuse.

| Level          | Description                                                                             | Points |
| -------------- | --------------------------------------------------------------------------------------- | ------ |
| **Excellent**  | Key values (speed, scoring, lives, timing, visuals) centralized in configuration files. | 5      |
| **Proficient** | Some configurability; a few hard‑coded values remain.                                   | 4      |
| **Developing** | Limited configurability.                                                                | 2–3    |
| **Beginning**  | No meaningful configurability.                                                          | 0–1    |

***
